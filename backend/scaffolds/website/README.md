# {project-name} — Device Dashboard (MERN)

A hosting-ready full-stack dashboard for the **{project-name}** hardware device.
This codebase is generated by Wireup's **Agentic Build** pipeline:

- **Hardcoded scaffold** — the infrastructure (Express API, React SPA, Vite,
  Vercel config, env plumbing) is pre-written and unchanged by the AI.
- **AI-generated parts** — the device-specific wiring only:
  - `backend/src/config/deviceEndpoints.ts` — how the backend reaches the device
    over your local network (or public endpoint).
  - `frontend/src/lib/deviceSpec.ts` — the sensors/controls the dashboard renders.

The AI never touches the plumbing. That keeps every build compiling and
deployable.

---

## What this is

The device runs firmware and exposes readings (sensors) and accepts commands
(actuators) over an HTTP endpoint on your local network. This MERN stack is the
companion web app:

```
Frontend (React + Vite)  ──HTTP──▶  Backend (Express + Mongo, optional)
                                        │
                                        └──HTTP──▶ Device (same Wi-Fi / LAN)
                                                   { device_ip }:8080/api
```

- The **backend** proxies live readings from the device and can persist history
  to MongoDB (optional — if `MONGO_URI` is unset it runs fully in memory).
- The **frontend** renders live values, historical charts, and control buttons
  from `deviceSpec.ts`.

## Local development

Requirements: Node 20+, `npm`.

```bash
# 1. Backend
cd backend
cp .env.example .env          # set DEVICE_IP, DEVICE_PORT, endpoints
npm install
npm run dev                   # API on http://localhost:8080

# 2. Frontend (in a second terminal)
cd frontend
cp .env.example .env          # VITE_API_BASE=http://localhost:8080/api
npm install
npm run dev                   # SPA on http://localhost:5173
```

> The device and your dev machine must be on the **same network** for the
> backend to reach the device at `DEVICE_IP`. If the device is exposed on the
> public internet, set `DEVICE_IP` to that public host instead.

### Endpoints (backend)

| Method | Path                          | Description                                  |
| ------ | ----------------------------- | -------------------------------------------- |
| GET    | `/api/health`                 | Liveness / service info                      |
| GET    | `/api/telemetry/live`         | Latest live readings proxied from the device |
| GET    | `/api/telemetry/history`      | Historical readings (Mongo, or memory)       |
| POST   | `/api/telemetry/control`      | Send a command to the device (actuator)      |
| GET    | `/api/device/info`            | Device identity + capability manifest        |

The API is stateless except for optional Mongo history. Live data is always
proxied straight from the device so it never goes stale.

## Deployment (Vercel)

`vercel.json` at the repo root wires both halves as one deployment:

- **Frontend** — built to `frontend/dist`, served as a static SPA.
- **Backend** — built to `backend/dist`, exported as a serverless function from
  `api/index.mjs` and mounted at `/api`.

```bash
npm i -g vercel
vercel --prod
```

The root `npm run build` compiles both the backend (`backend/dist`) and the
frontend (`frontend/dist`) before Vercel bundles the `api/index.mjs` function.

Then set these env vars in the Vercel dashboard (or `.env.production`):

```
DEVICE_IP=<public-ip-or-ip-of-device>
DEVICE_PORT=8080
DEVICE_ENDPOINTS_JSON={...}     # optional; defaults from deviceEndpoints.ts
MONGO_URI=<optional>
```

> **Deploying from the cloud?** Vercel functions run in the cloud, so they
> cannot reach a device on your home Wi-Fi. To use this hosting-ready app
> against a LAN device you have two options:
> 1. Expose the device with a tunnel (e.g. `cloudflared`, `ngrok`) and point
>    `DEVICE_IP` at the tunnel URL, or
> 2. Deploy the backend next to the device (Raspberry Pi / home server) and use
>    this repo's frontend as the cloud UI with `VITE_API_BASE` set to the home
>    server.

## Generated-by-config, not by hand

Editing a deployment is just editing the two AI-generated files:

- **`frontend/src/lib/deviceSpec.ts`** — add a sensor or button here and the
  whole dashboard updates (no component edits needed).
- **`backend/src/config/deviceEndpoints.ts`** — change how the backend talks to
  the device.

Everything else is plumbing you should never need to change.
